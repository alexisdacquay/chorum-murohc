## Operating rules for the successor

- The main session is the orchestrator. It launches PM, Engineer and QA as
  separate phases and does not silently combine their responsibilities.
- PM grooms before implementation. Engineer does not close the issue. QA does
  not fix defects. Merge and close only after QA PASS, including fresh
  post-merge verification. That loop is earning its keep: it caught a chore
  points field silently truncating 2.5 to 2, and it caught the login throttle
  contradicting the approved decision.
- The integration owner reviews the complete diff before merging rather than
  merging on a QA verdict alone.
- `chorum_murohc/api/urls.py` is a shared hotspot. Only one issue at a time may
  own it, so serialise the API tasks that register a route.
- Give every write-capable worker a fresh isolated worktree and a neutral
  `feature/...` or `maintenance/...` branch. Never add any AI-provider branding
  to repository text, branches, commits, code or tooling.
- Use GitHub CLI or API. Do not switch to a browser or display an account or
  login prompt without explicit user direction.
- Never read, source, print, copy, or expose `.env` or any secret value.
- Standing authority covers reversible task-local development: isolated
  worktrees, branches, approved locked installs, tests, generated test-only
  credentials, isolated test databases, disposable containers, and cleanup. Do
  not ask permission for those.
- Ask one clear question at a time, and only for a genuine product, security,
  rights, paid-service, production, or material-scope decision. Keep it short
  and lead with the recommendation.
- On a credit, quota, rate-limit, or capacity failure, save the checkpoint,
  retry after about 30 minutes, then approximately hourly. This session lost
  five delegated agents to a session limit and recovered by waiting for the
  reset rather than retrying in a loop.
